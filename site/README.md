# Arcade — сайт с каталогом игр

Сайт, который открывает мод Arcade для Claude Code: окно с библиотекой и играми, каталог и файлы игр. Только статика — ни базы, ни бэкенда. Хостинг — Cloudflare Workers (статика без кода).

## Как устроено

```
content/catalog.json   приставки и игры: описания, управление, где игра хранит счёт, лицензии
content/games/<id>/    ROM, текст лицензии и исходники каждой игры
web/                   окно Arcade: библиотека, игра, статистика, эмулятор Денди (JSNES)
build.mjs              собирает сайт в dist/
```

Сборка (`node build.mjs`) проверяет каталог и кладёт в `dist/`:

- `catalog.json` — каталог для окна и для мода;
- `files/<sha256>.nes` — файлы игр под именами-хешами: они не меняются, поэтому кешируются навсегда, а окно и мод сверяют скачанное с хешем;
- `files/<sha256>.nes.b64` — те же файлы в base64: мод в Claude Code скачивает файлы только как текст;
- `licenses/<id>/` — лицензии и исходники игр рядом с самими играми, как требует GPL;
- окно Arcade и `_headers` с правилами кеширования.

Ошибки в каталоге — нет файла, нет приставки, повтор id, адрес вне памяти, нет лицензии — останавливают сборку с понятным сообщением, так что битый каталог до пользователей не доходит.

В библиотеке есть кнопка **«Открыть свой ROM»**. Выбранный `.nes` читается локально браузером,
не загружается на сервер и не добавляется в каталог. Сохранение привязано к SHA-256 файла,
поэтому при повторном выборе того же ROM можно продолжить с прежнего места.

## Добавить игру

1. Положи ROM, текст лицензии и исходники в `content/games/<id>/`.
2. Допиши игру в `content/catalog.json`: приставка, название, жанр, описание, управление, путь к ROM и лицензия (название, автор, ссылка на исходники, файлы). Если знаешь, где игра хранит счёт, добавь `score` — тогда окно будет вести рекорды.
3. Запушь — Cloudflare Pages соберёт и выложит сайт сам.

Брать можно только игры со свободной лицензией, которая разрешает распространение.

## Развернуть на Cloudflare

Сайт — Worker без кода, только статика: `wrangler.jsonc` говорит Cloudflare выкладывать папку `dist/`.

1. В панели Cloudflare: Compute → Workers & Pages → Create application → Connect GitHub → выбери репозиторий.
2. Настройки:
   - Project name: `agent-arcade`;
   - Build command: `node build.mjs`;
   - Deploy command: `npx wrangler deploy`;
   - Root directory (Path): `site`, если сайт лежит в подпапке репозитория.
3. Deploy. Дальше каждый пуш в `main` выкладывает сайт заново. Адрес — `agent-arcade.<поддомен аккаунта>.workers.dev`.

## Сетевая игра

Кроме статики, у сайта есть небольшой код Worker'а — `worker/index.js`. Он вызывается только для адресов `/api/*` и `/net/*`, всё остальное Cloudflare отдаёт из `dist/` сам.

- `/api/ping` — проверка, что код работает.
- `/net/room/<имя>` — WebSocket в комнату. Комната — Durable Object (на SQLite, есть на бесплатном тарифе): каждое сообщение уходит всем остальным игрокам как есть, о входе и выходе приходят `{"type":"join"}` и `{"type":"leave"}`, новичок получает `{"type":"welcome","id":…,"peers":[…]}`. До 8 игроков, сообщение — до 1 МБ.

- `/net/doom/<имя>` — комната сетевого Doom (`DoomRoom`): пакеты doom-wasm уходят не всем, а адресату по номеру игрока; хозяин игры — номер 1, его первый пакет начинает новую игру. По образцу маршрутизатора Cloudflare doom-workers (BSD-3-Clause).

Движок Heretic для Blasphemer (heretic-wasm) — doom-wasm плюс Chocolate Heretic того же коммита Chocolate Doom: дерево сборки готовит `tools/heretic-wasm/prepare.py` (главный цикл Heretic — через `emscripten_set_main_loop`), собирает `.github/workflows/heretic-wasm.yml`, результат — в `vendor/heretic-wasm` с исходниками этой сборки. Blasphemer одному — без лобби, по сети — кооператив (`coop-blasphemer`), BlasphDM — deathmatch (`dm-blasphdm`); Heretic ищет файл игры под именем `heretic.wad`.

Движок сетевого Doom (doom-wasm, GPL-2.0) собирается в GitHub Actions — сценарий `.github/workflows/doom-wasm.yml`, запуск вручную — и лежит в `vendor/doom-wasm` вместе с архивом исходников.

- `/net/ejs/<номер игры>` и `/net/ejs/list` — сетевая игра EmulatorJS (`EjsGame`, один Durable Object на игру): комнаты, состав, пересылка нажатий и сохранений. Окно говорит с ним через `web/netplay-io.js` — сборка кладёт её вместо `emulatorjs/src/socket.io.min.js`, поэтому чужой сервер netplay.emulatorjs.org не нужен. Номер игры — первые 7 знаков хеша ROM.
- `/api/lobbies` — кто ждёт в сети (`Presence`): `{ doom: игроков в лобби FreeDM, games: { номер игры: открытых комнат } }`. Его раз в минуту спрашивает мод.

- `/net/board/<код>` — партия настольной игры (`BoardRoom`): ходы хранятся в SQLite этого Durable Object, места игроков — за жетонами в их браузерах, сервер следит за очерёдностью, правила проверяют оба окна (`web/board-rules.js` — реверси и русские шашки, шахматы — `vendor/chess.js`, BSD-2-Clause). Партию, которую месяц не трогали, комната удаляет сама.
- Игра с компьютером в настольных играх (`?game=chess&vs=bot`) — без сервера: в `web/board.js` «локальный сервер» с тем же разговором, что у комнаты партии, ходы — в localStorage. Боты: реверси — перебор на 3 хода с весами клеток (углы ценнее, соседи угла опасны) и подвижностью; шашки — на 4 хода, дамка втрое дороже шашки; шахматы — на 2 хода по материалу и положению фигур через chess.js. «Начать заново» меняет стороны.
- Игры приставок на EmulatorJS — явный выбор: обычный запуск — одному, кнопка «По сети» в полосе окна открывает меню сетевой игры эмулятора.
- Лобби кооператива Freedoom (`coop-<игра>`) и поиска соперника в настольных играх (`board-<игра>`) — обычные комнаты; они тоже сообщают, сколько людей ждёт, и `/api/lobbies` отдаёт это в полях `coop` и `board`.

### Ограничения

- WebSocket — только со страниц Arcade: подключение с чужого сайта (заголовок `Origin`) получает 403.
- С одного адреса — не больше 4 подключений в одну комнату (две вкладки для проверки проходят), иначе 429.
- Частота — «ведро жетонов» на каждого игрока, с двойным запасом на всплеск: лобби и комнаты друзей — 20 сообщений и 256 КБ в секунду, Doom — 400 и 512 КБ, игры EmulatorJS — 150 и 2 МБ (сохранение при выравнивании проходит кусками). Лишнее отбрасывается; кто долго превышает лимит, того комната отключает (код 1008).
- По-прежнему: до 8 игроков в комнате и до 1 МБ на сообщение.

Тест — `tests/worker.test.mjs`.

## Браузерные игры

Игры, написанные сразу для браузера (`kind: "web"` в каталоге): папка игры целиком лежит в `content/games/<id>/`, сборка кладёт её в `web-games/<id>/`, окно открывает страницу игры во встроенной рамке под своей полосой. Первая — HexGL (MIT): что изменено при подключении, написано в `content/games/hexgl/NOTICE.txt`.

**OpenTTD 15.3** собирается в GitHub Actions официальным способом (`.github/workflows/openttd-wasm.yml`), графика — OpenGFX 8.0. Свои скрипты Arcade попадают в страницу игры при сборке сайта (поле `inject` в каталоге): `arcade-opengfx.js` кладёт OpenGFX с нашего сайта в `/baseset` до старта, поэтому игра не качает графику с openttd.org. Сохранения — в браузере игрока (IndexedDB), как у OpenTTD.

**Warzone 2100 4.7.0** — официальная браузерная сборка из релиза игры на GitHub, её в репозитории нет: сборка сайта скачивает архив (поле `download` в каталоге), сверяет размер и SHA-256, кладёт его в кеш `.cache/` и распаковывает в `web-games/warzone2100/`. Правки страницы (`edit`) убирают счётчик Cloudflare Web Analytics и service worker, который кешировал бы игру на весь сайт; ролики кампании не выкладываются — игра их пропускает. Файлы больше 25 МиБ сборка сжимает gzip и режет на части, `arcade-parts.js` склеивает их в странице. Потокам игры нужен `SharedArrayBuffer`, поэтому у игры `isolated`: папка получает COOP и COEP в `_headers`, а окно с ней (`/?game=warzone2100`) — в `worker/index.js`. У игры и `offline`: `Content-Security-Policy: connect-src 'self'` не даёт ей самой спрашивать обновления у wz2100.net. Bootstrap 5.3.2 для оформления страница берёт не с cdnjs, а из `vendor/bootstrap/` (MIT) — те же файлы, `integrity` прежний. Пауза — `arcade-pause.js`: главный цикл и звук спрятаны в модуле Emscripten, поэтому страница сама даёт окну `arcadePause()`. Сохранения — в браузере игрока (IndexedDB).

## Вкладки и полки

В каталоге (`content/catalog.json`) кроме приставок есть группы (`groups`) и полки (`shelves`). У приставки может быть `group` — тогда отдельной вкладки у неё нет, а её игры живут во вкладке группы на своих полках (`shelf` у каждой игры; сборка требует полку у всех игр группы). Сейчас группа одна — «Игры» (`games`): полки шутеры, гонки, стратегии, настольные; в неё входят приставки `doom`, `board` и `web` (их id нужны движкам и адресам игр, но вкладок у них больше нет). Старые адреса `?tab=doom|board|web` открывают вкладку «Игры» на полке первой игры этой приставки.

## Книги

Книги каталога собирает `tools/books/build.mjs` по списку `tools/books/books.json`: английские — из Project Gutenberg (TXT), украинские — из украинской Викитеки (EPUB через ws-export; страница находится поиском и записывается в список). Разбор EPUB, FB2 и TXT — общий для сборщика и окна (`web/book-format.js`), чистка служебного текста источников — в сборщике. Результат — `content/books/<id>/book.json` и `LICENSE.txt`, список собранных — `content/books/index.json`: по нему сборка сайта заводит книги в каталог. Читалка окна — `web/reader.js`, закладка — абзац в начале экрана (localStorage).

## Языки

13 языков. Русский — исходный, английский — свой перевод, остальные — переводы поверх английского в `web/locales/<язык>.json`; сборка вставляет их в `i18n.js`. Язык — из `?lang=`, сохранённого выбора или языка браузера, иначе английский. Как переводить — `tools/i18n/README.md`.
